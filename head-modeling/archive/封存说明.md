# 封存说明

2026-10-01 按用户要求暂时停用六个业务板块。封存是保留源码并退出正式入口，后续可以选择性恢复。

| 位置 | 内容 |
| --- | --- |
| 停用功能/admin-web | 管理端整体，含原有环境与依赖目录 |
| 停用功能/user-app/src | 订单、支付、履约页面及组件、服务、工具 |
| 停用功能/backend | 订单、设备、库存、Agent、统计、数据库、队列、旧入口、旧测试及操作资料 |
| 历史工程 | 原根配置、启动部署脚本、端到端测试、备份及根依赖 |
| 历史文档 | 已退出当前权威说明的旧文档 |
| 演示与答辩 | 比赛材料、演示和 APK 说明，包括原有未跟踪的三份答辩文档 |
| GPU旧资料 | 多模型、穿透、CUDA 安装与旧部署资料 |
| 迁移前原件 | 本轮改写的重要入口与说明的原始副本 |

原始位置与目标位置见 ../docs/目录迁移清单.json，迁移前源码校验值见 ../docs/迁移前文件校验.json。
记录包含路径与哈希，不包含环境变量值。

## 恢复方式

1. 选定一个需要恢复的业务板块，先确认它的接口、依赖和数据来源。
2. 对照迁移清单把所需模块复制回正式目录，修复引用；不要整批覆盖当前建模入口。
3. 旧 app.js、app.fixed.js、app.server.js、app.real.js、app.llm.js 仅作参考；正式入口仍为 services/backend/src/app.js。
4. 恢复对应页面与 API 路由，并补齐该板块自己的依赖、测试和配置。
5. 区分模拟与真实服务，验收通过后更新功能清单与重构进度。

环境文件、依赖、日志和备份可能留在封存目录中，沿用忽略规则，不上传密钥与运行数据。
旧源码的相对路径仅在原目录布局下有效；封存目录不承诺可直接 npm start。
