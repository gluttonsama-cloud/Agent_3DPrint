# admin-web 3分钟答辩提纲

## 开场

大家好，我们项目聚焦的是 3D 头部建模和 3D 打印业务场景。  
这次我们重点展示的不是某一个孤立的 AI 功能，而是整套系统里的 `admin-web` 管理中台。

它的核心价值是两句话：

- 第一，它是业务运营中枢，负责订单、设备、库存和数据管理
- 第二，它是多 Agent 协作的可视化窗口，把 AI 决策过程真正展示出来

---

## 第一部分：为什么要做这个后台

在真实业务里，最难的不是某一个模型能力，而是整条链路怎么协同。

比如用户提交订单之后，系统要面对很多问题：

- 这个订单能不能进入生产
- 应该分配给哪台设备
- 当前材料够不够
- 如果设备故障怎么办
- 如果参数不合理，谁来辅助判断

我们希望解决的，就是把这些原本分散的环节，统一收敛到一个智能化后台里。

---

## 第二部分：admin-web 里有什么

`admin-web` 主要有 6 个核心模块。

第一是 Agent 可视化中心。  
这里可以看到协调 Agent、调度 Agent、库存 Agent 的协作过程，包括节点状态、消息流转、决策时间线和解释面板。  
我们还专门做了三种演示场景：正常流转、库存不足、设备故障自动重试。

第二是 Agent 管理。  
不仅能看 Agent，还能配置 Agent 的角色、能力和 System Prompt，为后续扩展提供基础。

第三是数据看板。  
它展示订单总量、待处理订单、打印中订单、设备利用率、设备时间线和库存预测，体现系统的运营视角。

第四是订单管理。  
支持订单筛选、批量处理、详情查看、状态时间线、Agent 决策历史和 AI 审核助手。

第五是设备管理。  
可以查看设备状态、任务进度，并通过实时通信接收设备进度更新；设备异常时还能触发 AI 诊断。

第六是库存管理和 3D 模型预览。  
库存模块负责材料数量、预警和补货建议；3D 模型预览则能直接查看 STL、OBJ 等模型文件，增强业务真实性。

---

## 第三部分：我们的亮点是什么

我认为这套后台最重要的亮点有 3 个。

第一，我们把多 Agent 协作过程可视化了。  
很多项目会说自己用了 Agent，但通常评委看不到协作过程。  
我们不仅用了，还把它变成了一个可以看、可以解释、可以演示的界面。

第二，我们把 AI 真正接入了业务流程。  
AI 不只是聊天，而是参与订单审核、设备诊断、库存判断和调度辅助。

第三，我们兼顾了演示效果和落地能力。  
系统既支持真实接口和实时事件，也支持本地模拟场景，所以既适合比赛现场展示，也具备继续落地的基础。

---

## 结尾

所以如果用一句话总结 `admin-web`，我会说：

**它不是一个普通后台，而是把 3D 业务流程、AI 决策能力和多 Agent 可视化真正融合起来的智能运营中台。**

我们想证明的不是“我们调用了模型”，而是“我们把智能体做成了一套能进入真实业务流程的系统能力”。
