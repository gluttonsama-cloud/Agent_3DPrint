# 项目说明

当前产品只覆盖：拍摄引导 → 上传照片 → 图像预处理 → AI 3D 生成 → 模型预览 → 下载。
用户端入口是 apps/ai-3d-head-modeler/src/App.tsx，API 入口是 services/backend/src/app.js。

## 本地开发

从仓库根目录执行，用户端和 API 分别在两个终端运行：

```powershell
./head-modeling/scripts/start-dev.ps1 -Target api
./head-modeling/scripts/start-dev.ps1 -Target user
```

首次安装分别进入 services/backend、apps/ai-3d-head-modeler 执行 `npm ci`。
用户端默认 http://localhost:3000，API 默认 http://localhost:3001；已有 .env 可覆盖配置。
环境文件随对应子系统保留。确认用户端 VITE_API_BASE_URL 指向 API，切勿提交实际密钥。
现有 Android 工程保留在用户端目录；本轮不重新打包 APK。

## 检查命令

```powershell
cd head-modeling/services/backend
npm test
cd ../../apps/ai-3d-head-modeler
npm run build
npm run lint
```

## Docker

```powershell
docker compose -f head-modeling/deploy/docker-compose.yml up -d --build
```

用户端端口为 8080，API 通过同源 /api 代理；没有启用管理端、数据库和业务队列。
后端环境文件是 services/backend/.env。构建上下文限制在各应用或服务目录，封存源码不会打包进去。
本地 rembg 是可选 gpu profile，目前未与 API 抠图链路接通；需要时单独部署和验收。
Docker 实际构建与运行状态以重构进度为准。

## 已知边界

- 任务状态在内存中，重启后无法恢复。
- 混元是当前生成主链。hybridScheduler 的 Replicate 自动降级尚未实现，不能视为已可用。
- 抠图 API 当前使用 PicWish；本地 rembg 保留作后续集成候选。
- 支付、订单、生产管理、业务 Agent 与运营统计已经封存。
- 当前保留页面沿用旧视觉和交互，后续逐块优化。

## 图像预处理（2026-10-02）

上传页先选正面照，可补充左侧、右侧等视角；接着进入预处理页，检查原图与实际建模输入。
支持方向修正、90°旋转、拖拽裁剪框、恢复原图、可选抠图。默认保留真人原貌；旧动漫化入口返回上传页。
裁剪可拖动角点或边缘缩放、框内移动，提供自由比例、正方形和 3:4；点击应用后才更新建模输入，
取消保留已确认结果。大图通过“处理结果／查看原图”切换对照，适配手机操作。
文件和 Base64 统一处理，最长边 2048、不放大小图、单图上限 3 MB，透明区域导出为白底 JPEG。
短边小于 512 时提醒换图；本轮没有人脸检测、模糊评分、美颜或 AI 补画。

抠图使用新入口 `POST /api/remove-background/inline`，请求 `{ image: "data:image/...;base64,..." }`，
成功返回 `{ success: true, image: "data:image/png;base64,..." }`。需配置 `PICWISH_API_KEY`。
协议依据：[PicWish 中国站官方文档](https://picwish.cn/background-removal-api-doc)。
新入口直接返回图片，不经过七牛云；旧抠图入口仍保留，不能把新入口测试当作旧入口验证。
默认仅本机调用；受信远程设备或代理须配置 `PREPROCESS_ALLOWED_IPS`，网页来源须配置
`PREPROCESS_ALLOWED_ORIGINS`（逗号分隔）。公开部署前应在网关加身份与配额控制。
新入口限制全局 2 个并发、每 IP 20 次/10 分钟、全局 60 次/小时；这些计数为进程内状态。

补充本地检查：用户端与后端各运行 `npm run test:preprocess`。
浏览器用例在用户端 `tests/preprocessing.browser.cjs`，先启动 Vite 4173 端口再运行；
需要本机 Playwright，必要时用 `PLAYWRIGHT_MODULE` 和 `TEST_CHROMIUM_PATH` 指定工具位置。
可用 `TEST_SCREENSHOT` 指定测试截图输出路径；生成与抠图 API 全部由测试拦截，不访问付费服务。

生成接口交接：`uploadPhotos` 接受 `preparedImage`，使用已确认的 Base64，避免再次压缩；
HTTP 请求维持 `photos`、`mode`、`enableBackgroundRemoval`，增加可选 `views` 数组保存同序视角。
当前后端尚未消费 `views`；生成提供方集成时需显式映射视角。单图提交 `single`，多图提交 `multiview`。

## 外部部署限制

当前图片预处理的本地检查不代表 Docker 或局域网部署验收。前端创建照片标识使用 crypto.randomUUID，需 HTTPS 或 localhost 等安全上下文；普通 HTTP 局域网地址可能无法选择照片，尚未提供兼容回退。

后端内联抠图按实际连接地址判断来源，默认只接受本机，不信任客户端提供的 X-Forwarded-For。Docker 中 Nginx 的容器地址默认不在信任列表，使用代理前须配置 PREPROCESS_ALLOWED_IPS，并按需要配置 PREPROCESS_ALLOWED_ORIGINS；不能把配置解析通过当成代理链路可用。容器运行、远程浏览器和真实 PicWish 调用尚未验收。
