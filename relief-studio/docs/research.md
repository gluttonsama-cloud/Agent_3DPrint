# 技术调研、成本与客户会议材料

调研日期：2026-09-05。本文区分官方资料、工程判断、本机实测和待客户确认事项。

## 结论

针对 LOGO、文字及少量色块，采用传统分区＋人工确认高度的路线。AI 分割作为候选辅助能力，
不让模型重新绘制标志文字。整个任务更准确地称为 **UV 堆墨 2.5D 浮雕制版**。
三维网格仅用于预览；打印所需数据以高度图和累计掩膜为核心。

本演示已实现上述数据链路，尚未验证任何特定设备的实物打印。

## 算法实现与代价

主流程统计全图 5-bit RGB 色箱，再按像素频次加权聚类代表色，将所有原图像素分配到区域。
不进行形态学开运算、去小区域或自动填洞。它保留空间上的细字，但颜色很接近的区域仍可能被
归入一类；用户应增加色数或手工修正。5-bit 色箱不是“最多 32 个颜色”的限制，而是每通道量化。

高度由用户指定的层数产生，不从颜色亮度推断真实深度。自动建议 0/5/10 层只用于开始编辑。
颜色替换、合并、选区和画笔都不调用云端。三维预览没有赋予每层真实毫米厚度。

SAM 2.1 tiny 使用独立环境、官方权重和 CPU float32，固定 4 线程，24 个正点＋24 个负点。
提示点来自演示分区，任务是一次选出分散的白字。三轮测试只证明这套部署可以运行及该提示策略
的效果，不能推断所有 SAM 提示方式均不适合。模型不随客户包分发。
详细测量和权重哈希见验证文档及 JSON 记录。

人工修正时间未测：目前没有客户确认的人工真值，也没有计时操作员实验。
下一轮应让操作员在同一批 10–20 张图上交替使用传统选区和 AI 辅助，记录点击数、修正时间、
细字错误和最终客户确认率，再判断是否值得接入。

## PC 兼容性与边界

Electron 负责 UI 与本地文件对话框；Python 程序通过 PyInstaller 自带运行时。
Windows 开发机已可打包。独立 EXE 的输入输出为文件式接口，可被其他 PC 程序调用，
不限定客户宿主编程语言。没有实现 DLL、COM、厂商专用协议或任意系统安装器调用。

产品包不含 WSL、PyTorch、SAM 模型或开发用 Node/Python 环境。
包中 Chromium 负责 WebGL，算法 CPU 运行。缺少 WebGL 时二维编辑与导出继续可用。
受限 PATH 的打包冒烟测试仅检查依赖是否随包，不能代替干净系统或客户现场验收。

## 五分钟会议演示顺序

1. 导入徽标，说明圆外不打印及样例的 55 mm 平面尺寸。
2. 点选白字，将层数从 10 改为 15，再撤销；展示高度可控。
3. 选择一个局部连通区域并划入新区域，展示手动纠正能力。
4. 切换 3D、旋转观察，再看第 1/5/10 层累计掩膜。
5. 保存重开，导出数据包，打开 manifest 说明设备适配仍待确认。

## 必须带回的客户信息

- 打印机厂家、型号、固件，墨水种类、喷头与通道配置。
- RIP 名称和版本、可接受输入格式、白墨/光油专色名及成功任务文件。
- 是否支持多次叠印、如何保持套准、设备总高度及抬头限制。
- 目标高度、最细文字/线条、成品尺寸、图像/矢量原稿。
- 金色来自金属底材、金属墨、烫金还是其他工艺。
- 允许的制作时间、单件成本与打样数量。
- 客户 Windows 版本、CPU、内存和显示环境。
- 需要独立工具还是嵌入现有 PC 软件；后者提供 SDK/API 文档与可测试宿主。

拿到设备后，先打印多个叠印次数的阶梯样，测高、检查边缘与套准，再定毫米换算与层序。
若设备不支持所需堆叠，保留软件演示成果并调整设备/工艺方案，不将算法成功等同于打印成功。
