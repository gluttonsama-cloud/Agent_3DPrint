# 倒角毫米宽度（RA09）

本次为源代码与本地 CPU/Electron 验证，不代表 RIP、打印设备或实物验收。

## 协议与界面

- 新请求：`{kind: 'bevel', widthMm: 正有限数}`。宽度单位为毫米。
- 兼容请求：`{kind: 'bevel', radiusPx: 1..128整数}`，保留既有像素距离算法。
- 同时提供 `widthMm` 与 `radiusPx` 时拒绝请求，包括其中一项为 `null` 的情况。缺失宽度、零、负数、布尔、字符串、NaN、无穷值均拒绝。
- 平滑继续使用 `{kind: 'smooth', radiusPx: 次数}`；不接受 `widthMm`。这只是旧协议字段名称，界面明确显示“平滑次数”。
- 高度面板默认使用毫米，可切换像素兼容；两单位的输入值与平滑次数分别保存，互不覆盖。毫米默认值为 0.5 mm。
- 毫米换算来自工程的 `sizeMm`，界面显示其宽、高。该尺寸为设计尺寸，不从图片 DPI 或设备标定曲线推断。修改工程尺寸后需重新倒角。

## 距离与保护定义

X 像素间距为 `sizeMm[0] / width`，Y 为 `sizeMm[1] / height`。非等间距时 NumPy 可分离欧氏距离变换分别使用两轴间距，不取平均值，不缩放图片。横向通过累积最近低面位置求距离，纵向通过抛物线下包络求平方距离最小值；每列的抛物线各入栈、出栈最多一次，单个台面包围盒的内存规模随像素数线性增长，没有逐像素遍历所有边界点。等间距采用 OpenCV `DIST_L2 / DIST_MASK_PRECISE` 快速路径：属于精确欧氏几何算法，不是 3/5 邻域近似，但 OpenCV 返回单精度浮点，仍有数值舍入误差。调用前后均检查取消；非等间距算法每 64 行检查取消。

距离以相邻低面**像素中心**为零点，保持原像素协议的采样约定。轮廓边界处的第一行打印像素，其距离是一格相应轴间距，而不是零；相对栅格单元边界有半格偏移。高度使用 `base + (level - base) * min(1, distance / widthMm)`，然后按既有规则四舍五入到整数层，非零台面最低保持一层。宽度小于一格时可能没有可见过渡；台面不足目标宽度时两侧过渡会相遇。

等高颜色交界不作为高度边缘；选区及 height 保护仅限制写入，不改变距离所用几何。低面采用同一台面邻接低面中的最高层数，避免多个底面最近点切换产生新接缝。透明孔不填充，已存在逐像素梯度保持不变。

修复了原算法的一处细线遗漏：洪泛虽然从有内部支撑的台面开始，却会把相连的一像素细尾、窄桥一并压低。现在以完整 2×2 同高台面作为支撑区，一像素宽的长细尾、窄桥及独立线保留原高；mm 与 px 分支均采用此修复。紧贴支撑区、恰有一个同高四邻居的单像素帽尖仍随台面倒角，以免圆形、菱形四极点留下高针。帽尖判定只扩张一次，不递归吞入长细线；一像素长凸起因此被解释为轮廓帽尖。该局部支撑判断是栅格规则，不保证任意低分辨率细节与高分辨率细节具有相同拓扑。

## 数值验证

先添加 mm 测试，旧实现因只读取 `radiusPx` 而全部失败；实现后通过。连接细尾/窄桥的四个 mm/px 组合先实测从 12 层错误降为 2 层，修复后保持 12 层，主体仍正常倒角。

`node scripts/python.cjs -m unittest discover -s engine/tests -p test_height_ops.py -v`：26 项通过，2.911 秒。包含既有 17 项回归与新增 9 项，覆盖物理宽度、两轴间距、斜向孔边距离、参数冲突、取消、保护/选区、连接细线、圆/菱形帽尖及等距快速路径 oracle。

设计 64×64 mm、目标宽度 2 mm、台面 200 层的单次实测（只计 `run_height`，不是性能承诺）：

| 分辨率 | 轴间距 | 首个满高点距离 | 与 2 mm 之差 | 耗时 |
| --- | --- | --- | --- | --- |
| 512×512 | 0.125 mm | 2 mm | 0 mm | 0.0310 s |
| 1024×1024 | 0.0625 mm | 2 mm | 0 mm | 0.1078 s |
| 2048×2048 | 0.03125 mm | 2 mm | 0 mm | 0.4364 s |

该测试允许误差为一格轴间距加整数层量化误差 `2/400 mm`；由于本例宽度恰好落在格点上，实际误差为零，不意味着所有栅格图案都能零误差。

独立暴力最短距离 oracle：非等距单测 36 组小矩阵及独立审查脚本另外 60 组随机形状/非方间距均一致；独立脚本最大绝对误差 `2.84e-14`。等距快速路径另与解析 oracle、NumPy 双精度路径对照，47×53、0.125 mm 间距实例的最大差为 `2.48e-7 mm`，在单精度误差容限内。

加入等距快速路径前，单台面 512/1024/2048 耗时分别为 0.1271/0.3996/1.4243 秒。同心三像素环 64/128/256 的耗时由 35.6/132.8/582.2 ms 降至 2.81/10.36/46.08 ms。完整台面包围盒仍逐个处理；大量嵌套同心环会重复处理包围盒面积，不能把单台面耗时视为所有图案上限。非方像素下的复杂嵌套台面性能仍属于 RA16 后续专项，不在本次强行重构。

新增 `tests/bevel-mm.spec.ts` 验证源代码 Electron 到真实 CPU 引擎：32×32 图案、8×16 mm 设计尺寸、1 mm 倒角，对全部 1024 像素断言解析高度，并检查保护、不改色/标签、撤销重做及保存重开。

`npx playwright test tests/bevel-mm.spec.ts --reporter=list`：1 项通过，总计 14.1 秒。使用本轮主代理统一构建的前端和当前 Python 引擎；证据位于 `artifacts/bevel-mm-1792905530218/`，包含输入、4 次保存、`report.json` 与 `bevel-mm-desktop.png`。截图已检查，毫米单位、1 mm 输入、8×16 mm 设计尺寸说明及平滑 3 次均正常显示。该合成几何用于验证非方像素换算与真实请求链路，不是实物视觉验收。

## 同轮集成注记：CPU 识别候选的资源路由

重新识别接入 v2 后，纯分色与已有主体蒙版的合并原先也会触发 GPU 交接、停止常驻模型。已在 `electron/engine-command.cjs` 集中定义 `requiresGpu(action, payload)`：`mode: 'color'` 或非 null 的显式 `subjectMask` 走 CPU；实际主体预测及 import 保留 GPU 路由。`subjectMask: null` 与省略字段保持 Python 既有语义，表示尚未提供主体结果，不能误送 CPU 后再尝试加载模型。

`electron/v2.cjs` 保留原始任务 action，单独记录 GPU 占用标记，CPU 候选跳过 `prepareEngine`；因此 `main.cjs` 原有停止常驻模型的回调不再被这类候选触发。取消、超时、退出清理及保存/导出原子提交行为沿用原 action。显式非 null 蒙版须先是普通对象，禁止自定义 JSON 转换；NaN、无穷值、Date、数组与标量在 IPC 创建任务前拒绝，防止 JSON 隐式转 null 后意外触发主体预测。普通对象的尺寸、编码与 0/1 数据仍由真实 Python dispatcher 严格校验，路由并不认定其内容有效。

先添加入口选择、CPU 不等待/不占 GPU 标记、CPU 取消三项回归并观察失败，再修改实现；独立审查补出的 NaN/Date 序列化回归也先红后绿。`npm run test:ipc` 最终 17/17 通过，0 失败、0 跳过，9.134 秒。包含真实本地 CPU 引擎的有效蒙版成功，以及错误尺寸、非 0/1 蒙版、缺字段对象、非法快照、非法选区五种请求被后端拒绝；GPU 交接期间取消实际主体识别或导入均不启动新进程。该验证不代表实机 GPU 显存或模型加载性能测量。
