# 重新识别的人工保护与候选提交

日期：2026-10-25。范围：RA07，源码工作台与真实 Electron IPC。此记录不代表 GPU 模型质量、安装包、RIP 或设备验收。

## 使用行为

- 已打开工程点击“重新识别区域”，默认勾选“保留人工修改”。有选区时默认仅处理当前选区，无选区时显示“整张工作图”；可明确切换。
- 自动分色继续使用 CPU 分色，不会把普通分色改成自动主体提取。主体提取仍由用户主动选择；新图片导入继续使用原有导入流程。
- 分析输入取工程 `original`，人工改色保存在 `colors`。重新识别不会把人工改色当成原始材料色，也不会修改 `original`。
- 保留模式尊重范围、颜色、高度三个保护位；已有打印像素的混合高度继续保留。复用原区域 ID 时保留用户区域名称。涉及范围与高度冲突时保留原标签和原高度，避免出现“不打印却有高度”的非法像素。
- 取消勾选会显示覆盖说明：仅在所选范围内替换识别区域、恢复原色、重算高度并清除人工保护位。分色覆盖高度为 0；主体覆盖使用明确设置的主体层数，零层背景保持 0。
- “保留零层背景”仅用于主体路线。颜色路线显式标记背景时，部分排除和全部排除采用一致行为；不会因先前主体路线留下的背景选项而恢复已排除范围，人工保护仍按当前策略合并。
- 选区外的标签、彩图、高度和保护位逐像素保持不变；在范围外仍被引用的区域元数据不会被复用改写。恢复保护标签之后再清理无引用区域，避免保留标签指向已删除的区域。

## 候选与历史

原来的重新识别 `RecognitionDialog → legacyEdit` 已移除。重识别采用 `RecognitionRequest → v2:recognition → EditPatch → EditorStore.accept`，自动结果不会被错误标记成全部人工修改。

对话框缓存并显示真实候选的 `labels` 和 `colors`。人工绿色在预览中仍显示绿色；被保护的打印像素在“标记背景”后仍可见。背景排除和恢复也通过正式候选重新计算，预览与应用使用同一份候选。

“应用识别结果”提交已经展示的候选，不再重复推理。范围、保护策略、路线、主体高度等参数改变后候选失效，需要重新生成预览；空主体不能直接应用以清空整图。取消中止当前请求，迟到成功不会回写工程。快照的 session/revision 在提交时再次检查，后续编辑、撤销或换工程都会使旧候选过期。

标签、颜色、高度、保护位和区域属性组成一个历史步骤；撤销和重做一并恢复。新导入原有主体颜色的“合并同色系明暗”选项保留，重识别的 v2 分色也传递同一显式选项，默认关闭。

## 协议补充

`RecognitionRequest` 新增可选 `mode`、`colorCount`、`tolerance`、`mergeMaterialShades`、`defaultLayers`、`subjectMask`、`excludedMask`。省略 mode 保持原 v2 主体识别语义。主选区、显式主体和排除蒙版均使用同尺寸、uint8、0/1 栅格；Electron 请求使用 base64-le 编码，后端验证尺寸、类型和取值。

## 本轮验证

先写失败回归并观察失败：原接口缺少色彩模式/主体掩膜参数、服务未编码新蒙版、旧界面没有默认保护选项、旧预览在人工擦除处 alpha 仍为 255、保留模式覆盖用户区域名称。相应实现后转绿。

- `node scripts/python.cjs -m unittest discover -s engine/tests -p test_recognition_ops.py -v`：16 项通过。覆盖原图分析、人工范围/颜色/混合高度、局部覆盖、保护位、用户命名、显式主体、明暗合并、SAM 参数、透明孔洞、取消和 2048 局部坐标。终审追加颜色路线部分/全部背景排除一致性回归，先复现全排除被 `keepBackground` 错误恢复，再限制该选项只在主体路线生效。
- `npm test -- src/capability-service.test.ts src/editor/store.test.ts`：9 项通过。覆盖正式栅格编码、取消后成功迟到、候选版本和原子撤销重做。
- `npm run build`：通过。
- `npx playwright test tests/recognition-protection.spec.ts tests/subject-colors.spec.ts tests/recognition-v2.spec.ts`：6 项通过。真实 Electron IPC 与 Python CPU 分色，包含原有新导入两种明暗策略、保存重开、2048 局部识别。
- 随后增加范围/高度参数失效与空主体禁用断言，`npx playwright test tests/recognition-protection.spec.ts`：2 项再次通过。该测试逐像素比较选区外四栅格、撤销/重做/重开结果，检查候选画布人工颜色和受保护背景像素，并延迟真实 CPU 结果的 IPC 投递验证取消迟到成功。

主体边界操作的桌面测试使用固定模型掩膜，后续分色与保护合并仍为真实 CPU 引擎；不将该结果称为真实 GPU 提取验收。生成证据保存在 `artifacts/recognition-protection-*`，不属于提交内容。完整回归和最终整合由当前主代理另行记录。
