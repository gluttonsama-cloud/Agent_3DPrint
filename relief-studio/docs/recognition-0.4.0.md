# 主体整体提取 0.4.0

## 改动

- 自动主体改用官方 BiRefNet_HR（2048×2048、FP16），直接返回一份前景掩膜。
- SAM 2.1 tiny 保留用于点击局部修正，不再运行自动网格候选或让用户勾选部件。
- 点击补选执行集合并，点击排除执行集合差；只取预测中包含点击点的连通部分。
- 画笔与点击可以交替使用，不丢弃之前的修边；支持最近 20 步主体撤销及原图对照。
- 保留暖白、深绿、铜金界面。背景彩色保留、层数为 0，主体统一使用指定高度。
- 工程格式仍为 v1。已保存工程不会自动重分区，应用识别结果仍可在工程中整步撤销。

## 来源和实验

官方代码与模型：https://huggingface.co/ZhengPeng7/BiRefNet_HR

固定版本 a7a562f6fd16021180f2f4348f4de003a2d3d1e1，模型 SHA256：
`9d678bafec0b0019fbb073b7fd02f05ede25dc4b15254f23b2fb0be333200c0d`。
第三方 Python 文件原样保存在 engine/vendor/birefnet，附 MIT 许可和来源记录。
使用静态导入和 local_files_only，不在运行时下载代码或上传用户图片。

对用户提供的京瓷效果图比较了：旧 SAM 候选流程、BiRefNet 标准权重的
1024/1536/2048 输入，以及 BiRefNet_HR 的 2048 输入。HR 的文字和细线视觉表现更完整，
选为本次默认；提高标准权重的输入尺寸并不稳定改善所有小物体。

本机 RTX 5070 Laptop GPU：HR 首次主体调用 7.51 秒，峰值显存约 5125 MiB；
第一次 SAM 点击含初始化约 2.09 秒，后续两次约 0.060 秒（不含人工操作时间）。

上述为开发运行时；PyInstaller 独立模型 EXE 在 PATH 仅保留 System32、开启
HF_HUB_OFFLINE 和 TRANSFORMERS_OFFLINE 时实际成功预测，首次请求耗时 68.24 秒。
桌面完整冷启动测试也出现超过 90 秒测试时限的情况，因此不能沿用开发运行时的
7.51 秒作为分发包性能。冷启动优化仍待完成，功能回归给予独立的较长时限。

自动初选已排除左下彩色炫光和右下生成标记，主要标志及中英文合并为主体。
左下水滴部分缺失、两颗小水滴漏选；三个固定测试点击补回这三处。
自动结果仍存在局部光线边缘误选及轮廓误差，不能将本次观察表述为全自动生产精度通过。

原始实验文件：artifacts/birefnet-trial；最终脚本 scripts/benchmark_foreground.py，
输出 artifacts/foreground-040 下的 automatic、three-clicks 掩膜、预览和示例工程。
提示点仅在测试脚本中，不参与产品算法。没有完整人工参考掩膜，IoU 和人工修正耗时留空。

## 验证

- 13 项 TypeScript、19 项 Python 单元测试通过，含局部加减、细小区域及孔洞保留。
- 开发桌面真实 GPU 测试通过：整体提取、补选、排除与撤销、无候选列表、背景零层。
- 打包版 5 条桌面流程全部通过（分次运行）：4 条常规回归通过，GPU 流程以
  180 秒独立测试时限通过，实际约 1.3 分钟，包含取消、重新提取、画笔、点选、撤销和保存。
- 示例加载测试补上等待区域加载的条件，避免测试自身连续请求触发任务锁。
- 只读代码审查未发现高优先级阻塞问题。

分发目录：release/0.4.0/win-unpacked；内含独立 model-runtime，可直接打开桌面 EXE。
样图工程和自动/三次补选对照图位于 release/0.4.0/samples。

模型运行时继续独立分发，新增 birefnet-hr/model.safetensors 和 config.json。
旧版仅包含 SAM 的模型包不能提供新版整体提取，必须更新。
