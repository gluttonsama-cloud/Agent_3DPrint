# 局部框选补选与模型对照

## 交互与实现

主体提取新增“框选补选”。在原图拖框，松开后使用 SAM 2 的 box 提示识别。
无需先运行整体提取；结果加入当前主体，不覆盖框外选区，支持撤销。
框宽高至少 8 px，支持反向拖动；取消操作或关闭对话框仍使用现有任务取消机制。
空结果不生成历史记录，界面提示缩小范围或使用画笔。

IPC 使用既有 `action: predict`，新增可选 `box: [left, top, right, bottom]`，
坐标以原图像素为单位，右下边界不包含。仅框提示时 points 可省略。
后端验证整数、范围和最小尺寸，并将输出限制在框内、alpha 可见和 validMask 有效范围的交集。
前端接收与原图等尺寸的掩膜，按并集补选，避免局部坐标偏移。

## 公开样本对照

使用此前下载的 Magnolia Cafe 霓虹照片，工作图为 960 × 720。
来源与 CC BY-SA 4.0 署名见 [公开图片评估](web-image-evaluation-20260907.md)。
手动框选两处区域，框位固定后分别调用 BiRefNet_HR 局部裁剪与 SAM 2 框提示。
这些是人工提示后的结果，不作为自动识别准确率。

| 区域、框坐标 | BiRefNet 局部输出像素 | SAM 框提示输出像素 |
| --- | ---: | ---: |
| OPEN `[445,305,760,565]` | 406 | 35591 |
| CAFE `[390,100,750,315]` | 0 | 27128 |

BiRefNet 局部裁剪依然漏选，CAFE 返回空掩膜，因此没有作为框选界面的默认算法。
SAM 返回了可用的局部对象，但 OPEN 包含招牌底板，CAFE 也包含字周围结构；
不能宣称精确提取霓虹文字。适用流程为框选对象后，再点击排除或画笔细修。
两种方法的结果均验证框外像素为零。

SAM 首次请求约 3.21 秒，复用同一图像编码后的第二次约 0.020 秒，
本次进程峰值显存约 556 MiB；BiRefNet 首次约 30.18 秒、第二次约 1.22 秒，
峰值显存约 5125 MiB。均为本机单次观测，不作客户硬件性能承诺。

## 验证

生产构建与 23 项 Python 测试通过。新增后端测试覆盖局部坐标映射、有效范围、
框外不选、原图不变、非法框与空框拒绝。
桌面交互测试通过，使用替代模型 IPC 验证反向拖框坐标、过小框拒绝、
框外画笔保留、撤销恢复和保存标签。真实 GPU 推理另由上述两例对照验证。
